# 成果物

成果物（`Artifact`）は、開発者が作り、保守するもの。次の4つからなる。

| 構成 | 意味 | 何と関係するか |
| --- | --- | --- |
| 要求（`Requirement`） | 振る舞いが満たすべき条件 | 振る舞い全体が要求を満たす |
| 振る舞い（`Behavior`） | 成果物が何をするか | 実装全体が振る舞いを実現する |
| 実装（`Implementation`） | コード | |
| 設計ルール（`Rule`） | 実装が従う決まり。要求でも振る舞いでもない | 実装一つずつがルールに適合する |

振る舞いは複数の実装の協調で実現されるので、実装全体を相手にする。設計ルールは各実装の書き方の決まりなので、実装一つずつを相手にする。

## 正しさと適合

成果物については、二つの性質を問える。

- 正しい（`Artifact.Correct`）：どの要求も振る舞い全体が満たし、どの振る舞いも実装全体が実現する。
- 適合する（`Artifact.Conforms`）：どの実装も、すべての設計ルールに適合する。

どちらも成果物が持つかもしれないし持たないかもしれない性質で、構造体のフィールドにはしない。バグのある成果物や、ルールに違反している成果物も表せるようにするためである。

## 変更要件

変更要件（`Artifact.ChangeRequest`）は、要求・振る舞い・設計ルールをどう変えるかを持つ。実装の変更は持たない。変更前の状態ではなく変え方（関数）として持つので、どの時点の成果物にも当てられる（`Artifact.ChangeRequest.apply`）。Issue と PR の範囲は、この変更要件を持つ（[Issue](../Issue/issue.md)、[PR](../PullRequest/pull-request.md)）。
