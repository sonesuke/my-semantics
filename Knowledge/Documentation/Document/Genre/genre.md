# 文書の種類

文書の種類（`Genre`）は、レイアウト（節の並び）が満たすべき決まり（`Genre.layout`）と、節をまたいだ文体が満たすべき決まり（`Genre.style`、言い直さない、など）と、内容を節にする方針（`Genre.place`：どの話題の事柄を、どの役割の節に置くか）を持つ。提案書と PREP 法は、話題と同じ名前の役割の節に置く（`Genre.sameName`）。よいレイアウトは種類によって違うので、種類が持つ。文書を種類に従わせることが、読みやすくする戦略になる。

[役割](../document.md)（結論、理由、判断してほしいことなど）は、種類が生み出すものではない。種類がなくても読む人に対する働きとして存在し、種類はそれを選んで並べる。具体的な役割は、それを使う種類のところで定める。節ごとの文体は役割が持つので、種類が持つ文体は節をまたいだものだけである。

並びの決まりは、決まった並び（`Genre.fixed`）か、順序を守り必須の役割を含む並び（`Genre.ordered`）で書く。役割は名前で比べる。

## 提案書

提案書（`proposal`）は、読者に提案を受け入れるかを判断してもらう文書。判断は受け入れるか受け入れないかの二値なので、受け入れたら何が起きるかを提案の中で過不足なく書く。

| 役割 | 働き | ふさわしい文体 |
| --- | --- | --- |
| 背景 | 課題を理解する前提を与える | 具体的 |
| 課題 | 何が問題かを示す | 具体的 |
| 提案 | 受け入れたら何をするかを示す | 言い切る、具体的 |
| 効果・費用 | 受け入れた場合と受け入れない場合の差を示す | 具体的 |
| 判断してほしいこと | 受け入れるかと、その期限について、何に答えればよいかを示す | 依頼する、はい／いいえで答えられる、新しい語を導入しない |

役割を、背景 → 課題 → 提案 → 効果 → 費用 → 判断してほしいこと、の決まった順に並べる。判断は提案を前提にするので、最後に置く。節をまたいでは言い直さない。

## PREP 法

PREP 法（`prep`）は、結論を先に示してから、理由と具体例で支持し、結論を繰り返す。役割を、結論 → 理由 → 具体例 → 結論、の決まった順に並べる。結論は新しい語を導入せずに言い切り、理由は結論とのつながりを示し、具体例は具体的に書く。繰り返す結論も含めて、言い直さない。

開発の PR の文書の種類は、開発の知識に置く（[PR](../../../Development/PullRequest/pull-request.md)）。
