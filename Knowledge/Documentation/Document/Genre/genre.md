# 文書の種類

文書の種類（`Genre`）は、節の役割と、取るべきレイアウト、節の役割ごとに取るべき文体、節をまたいで取るべき文体を定める。よいレイアウトと文体は種類によって違うので、種類が持つ。文書を種類に従わせることが、読みやすくする戦略になる。

レイアウトは、決まった並び（`Genre.fixed`）か、順序を守り必須の役割を含む並び（`Genre.ordered`）で表す。

## 提案書

提案書（`proposal`）は、読者に提案を受け入れるかを判断してもらう文書。判断は受け入れるか受け入れないかの二値なので、受け入れたら何が起きるかを提案の中で過不足なく書く。

| 節 | 取るべき文体 |
| --- | --- |
| 背景・課題 | 具体的 |
| 提案（受け入れたら何をするか） | 言い切る、具体的 |
| 効果・費用（受け入れた場合と受け入れない場合の差） | 具体的 |
| 判断してほしいこと | 依頼する、はい／いいえで答えられる、新しい語を導入しない |

節をまたいでは言い直さない。判断は提案を前提にするので、最後に置く。

## PREP 法

PREP 法（`prep`）は、結論を先に示してから、理由と具体例で支持し、結論を繰り返す。結論は新しい語を導入せずに言い切り、理由はつながりを示し、具体例は具体的に書く。

## PR

PR（`pullRequest`）は、レビュアーに承認するかを判断してもらう文書。要約・範囲・変更・検証・逸脱の理由・判断してほしいことの順に並べ、逸脱の理由は逸脱があるときだけ置く。承認したら何を受け入れたことになるかを、範囲・変更・検証で過不足なく書く。開発の PR のモデル（[PR](../../../Development/PullRequest/pull-request.md)）を、文書として読みやすく並べたものにあたる。
